📋 Project Synopsis

SkyBooker is a comprehensive microservices-based airline management and flight booking platform. It caters to multiple actor types: System Administrators who oversee operations, Airline Staff who manage their respective airline's flights, and Passengers who discover destinations, book tickets, and receive real-time notifications.

The architecture emphasizes strict multi-tenancy for airline staff, ensuring isolated data views per organization. It utilizes an API Gateway for routing and unified Swagger documentation, RabbitMQ for asynchronous event-driven notifications (like flight delays), and a suite of decoupled domain services for high availability and scalability.

📝 Detailed Requirements

Identity, Multi-Tenancy & Access Control

  • Role-Based Access Control (RBAC): Support for ADMIN, AIRLINE_STAFF, and PASSENGER roles. Admins manage master data (Airports, Airlines), Airline Staff manage flights, and Passengers book them.
  • Airline Staff Multi-Tenancy: Strict data isolation ensures airline staff can only view, create, edit, or manage flights associated with their specific `airlineId`. The authentication context carries this tenancy ID transparently.
  • Platform-Wide Validation: Active-status filtering enforces that flights can only be queried or managed if their parent Airline and origin/destination Airports are actively marked as `isActive`. Staff logins are disabled if their parent airline is deactivated.
  • Unified API Gateway: Validates JWTs, injects user context, and provides an aggregated Swagger UI for cross-service API discovery.

Flights, Airports & Operations

  • Airport & Airline Management: Admins can toggle the active status of entities across the platform. Jackson JSON serialization ensures strict boolean mapping for `isActive` flags across all DTOs and entities.
  • Dynamic Flight Discovery: A specialized `GET /flights/by-destination` API empowers a "Popular Destinations" UI flow, allowing passengers to filter flights effortlessly based on destination metrics.
  • Airline Operations Dashboard: React-based frontend providing persistent session handling (via localStorage hydration) to ensure stable page refreshes for complex admin and staff dashboards.
  • Profile Data Integrity: Jakarta validation applied to Staff Profiles, ensuring regex compliance for names, phone numbers, and profile photo URLs across both frontend forms and backend models.

Bookings & Event-Driven Notifications

  • Booking Lifecycle: Manages the complete transactional state from initial seat reservation through payment success or failure.
  • RabbitMQ Event Bus: The Flight Service publishes status update events (e.g., DELAYED, CANCELLED) to RabbitMQ exchanges.
  • Asynchronous Notifications: The Notification Service acts as a consumer, querying the Booking Service for impacted passengers and dispatching HTML email updates via SMTP seamlessly.
  • Real-time UI Consistency: Frontend clients utilize periodic polling to sync local states with the backend flight updates gracefully.

💾 Database Strategy

SkyBooker leverages the Database-per-Service pattern, ensuring complete domain isolation and preventing tight coupling between modules.

  • admin_db: System configurations, master user mappings.
  • airline_db: `airlines` (id, name, isActive), `airports` (code, city, isActive).
  • flight_db: `flights` (metadata, schedules, airline references).
  • booking_db: `bookings`, `tickets`, `seat_allocations`.
  • passenger_db: `passengers`, `travel_documents`.
  • payment_db: `transactions`, `invoices`.
  • notif_db: `email_logs`, `audit_events`.
⚡ Non-Functional Requirements
RequirementImplementation Detail
SecurityStrict context propagation. Airline Staff cannot modify flights outside their `airlineId`. Frontend prevents unauthenticated redirects via `isAuthReady` checks.
Data IntegrityJackson annotations (`@JsonProperty`) explicitly handle boolean `isActive` parsing to avoid serialization bugs. Jakarta validations enforce profile integrity.
Test CoverageJacoco integration enforces maximum coverage. Dedicated coverage tests account for lombok-generated code, DTOs, edge cases, and custom exception handlers.
Asynchronous ResiliencyRabbitMQ unblocks main request threads. If SMTP goes down, RabbitMQ queues retain messages until the Notification Service recovers.
UsabilityFallback images integrated dynamically for destination cards. Clean Swagger UI integration ensures developer ease of use.
🔮 Future Enhancements
  • Dynamic Pricing Engine: Implement yield management algorithms to adjust flight prices automatically based on seat availability and time-to-departure.
  • Loyalty Program (SkyMiles): Add a new microservice to track frequent flyer points, enabling passengers to book using points.
  • Mobile Boarding Passes: Generate Apple Wallet / Google Wallet pass files dynamically from the Booking Service.
  • Redis Caching: Cache the "Popular Destinations" API response in Redis to reduce database strain on high-traffic landing pages.
  • Distributed Tracing: Integrate Zipkin or Jaeger to map trace IDs across flight creation and RabbitMQ asynchronous flows.
