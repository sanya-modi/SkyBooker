================================================================================
                    SKYBOOKER - DETAILED CLASS DIAGRAM
                    Airline Ticket Booking System
                    Microservices Architecture
================================================================================

PROJECT OVERVIEW:
-----------------
SkyBooker is a comprehensive airline ticket booking system built using 
microservices architecture with Spring Boot. The system consists of 9 core 
services handling authentication, flight management, booking, payments, 
notifications, and administrative functions.

================================================================================
                        MICROSERVICES ARCHITECTURE
================================================================================

1. AUTH-SERVICE (Port: 8081)
2. FLIGHT-SERVICE (Port: 8082)
3. SEAT-SERVICE (Port: 8083)
4. BOOKING-SERVICE (Port: 8084)
5. PASSENGER-SERVICE (Port: 8085)
6. PAYMENT-SERVICE (Port: 8086)
7. NOTIFICATION-SERVICE (Port: 8087)
8. AIRLINE-AIRPORT-SERVICE (Port: 8088)
9. ADMIN-USER-SERVICE (Port: 8089)

                                  ↓

                                  ↓

================================================================================
                        KEY DESIGN PATTERNS
================================================================================

1. MICROSERVICES PATTERN
   - Each service is independently deployable
   - Database per service pattern
   - Service-to-service communication via REST

2. REPOSITORY PATTERN
   - Spring Data JPA repositories
   - Custom query methods
   - JPQL for complex queries

3. DTO PATTERN
   - Request DTOs for input validation
   - Response DTOs for data transfer
   - Entity-DTO mapping

4. ENUM PATTERN
   - Type-safe status management
   - FlightStatus, BookingStatus, PaymentStatus, etc.

5. AUDIT PATTERN
   - Automatic timestamp management (@PrePersist, @PreUpdate)
   - Audit logs for admin actions

6. SOFT DELETE PATTERN
   - isActive flag for logical deletion
   - Maintains data integrity

================================================================================
                        INTER-SERVICE COMMUNICATION
================================================================================

Services communicate via:
1. REST API calls (RestTemplate/WebClient)
2. RabbitMQ message queues (for notifications)
3. Shared reference IDs (userId, flightId, bookingId, etc.)

Example Flow - Booking Creation:
1. User creates booking → Booking Service
2. Booking Service → Flight Service (check availability)
3. Booking Service → Seat Service (hold seats)
4. Booking Service → Payment Service (process payment)
5. Payment Service → Notification Service (send confirmation)
6. Notification Service → User (email/SMS)

================================================================================
                        SECURITY & VALIDATION
================================================================================

1. JWT-based authentication (Auth Service)
2. Role-based access control (PASSENGER, ADMIN, AIRLINE_STAFF)
3. Input validation using Jakarta Validation
4. Password encryption (BCrypt)
5. OAuth 2.0 integration (Google)
6. CORS configuration
7. Global exception handling
